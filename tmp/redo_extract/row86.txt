Abstract
Agent skills extend LLM agents with reusable instructions, scripts,
tool bindings, and contextual dependencies. However, current skill
ecosystems largely rely on trust-based loading and static inspection,
leaving a gap between what a skill can inject into an agent’s context
and what it can cause the agent to do at runtime. This gap introduces
new security and privacy risks, and existing defenses primarily in-
spect skill files statically or regulate individual tool calls, without
systematically connecting a skill’s declared intent with its run-
time behavior. In this paper, we present SkillGuard, a skill-centric
permission framework that treats skills as permission-bearing ex-
ecutable artifacts. SkillGuard introduces a dual-plane governance
model that jointly regulates context influence and action side ef-
fects through skill manifests, runtime access control, user-mediated
authorization, deny-by-default enforcement, capability inference,
and behavior monitoring. We evaluate SkillGuard on 315 real-world
skills and SkillInject. The permission taxonomy covers 99.76% of
observed protected objects, and automated manifest generation
reaches 91.0% F1. In adversarial evaluations, SkillGuard reduces
attack success from 32.37% to 23.02% for contextual injections and
from 25.56% to 16.67% for obvious injections, while maintaining
benign task utility. These results suggest that SkillGuard, as a skill-
centric permission framework, can provide a practical foundation
for improving the privacy and security of agent skill ecosystems.

Introduction
The rapid evolution of large language model (LLM) agents has
led to a new programming paradigm centered around agent skills:
modular, reusable packages that encapsulate natural language in-
structions, code specification, tool bindings, scripts, and contextual
dependencies [15, 18]. These skills are increasingly used to extend
agent capabilities in real-world systems, enabling complex work-
flows such as software engineering [12], data analysis [3], and
enterprise automation [17]. However, this shift also introduces a
fundamentally new security and privacy challenge: skills are not
merely passive resources but active behavioral units that can shape
both what an agent knows and what it does.
Recent studies have demonstrated that LLM agents are vulner-
able to a wide range of attacks, including prompt injection [14],

memory poisoning [32], and malicious tool usage [20], which can
lead to unauthorized actions such as data exfiltration or financial
transactions. These risks are further amplified in the skill-based
ecosystem, where third-party or dynamically loaded skills may
introduce hidden instructions, implicit contextual dependencies,
or transitive interactions across tools, agents, and external ser-
vices. Unlike traditional software components written in formal
programming languages, skills are often loosely composed of natu-
ral language, code, and data. While such customized components
provide flexibility and convenience for skill developers, their hetero-
geneous and semi-structured nature poses significant challenges for
program analysis, thereby limiting the ability to inspect, constrain,
and verify their behavior across diverse attack surfaces.
Recent work on agent security has begun to address related prob-
lems, but existing approaches remain fragmented and incomplete
for the skill setting. One line of work focuses on action-level privi-
lege control. For example, Progent [29] introduces a programmable
policy framework that intercepts tool calls at runtime and enforces
fine-grained allow/forbid decisions over tool invocations, argu-
ments, fallback actions, and dynamic policy updates. Similarly,
AgentBound [8] provides a declarative access-control framework
for MCP servers, combining manifest-style permission declarations
with sandbox-based enforcement to restrict filesystem, network,
secret, and process access. These systems are effective for mitigat-
ing over-privileged tool use and execution-boundary violations,
but they primarily govern downstream actions. However, they do
not regulate how a skill is loaded, what instructions it injects into
the agent’s context, what auxiliary dependencies it introduces, or
how it shapes the agent’s reasoning before any tool call occurs.
Conversely, context-oriented defenses such as A2AS [21] introduce
mechanisms such as authenticated prompts, security boundaries, in-
context defenses, and codified policies to protect context-window
integrity, but they do not provide a systematic skill-centric permis-
sion model that connects context admission, runtime grants, tool
use, delegation, and enforcement.
This gap is fundamental because agent skills operate across
two coupled planes. On the context plane, a skill can introduce
instructions, examples, retrieved documents, memory fragments, or
hidden assumptions that reshape the agent’s reasoning trajectory.
On the action plane, a skill can trigger tool calls, access files or
secrets, execute code, communicate over the network, or delegate
work to other agents, skills, and MCP servers. Existing approaches
typically secure one plane but not the other. A tool-level policy may
block an unsafe action, but it may miss malicious context that steers
future reasoning. A context-level defense may mark untrusted input,
but it may not constrain the concrete side effects caused by a skill

after it is accepted. Securing skills therefore requires a proactive
runtime governance mechanism that treats skill loading, context
construction, permission granting, and action execution as jointly
enforceable security decisions.
In this paper, we propose SkillGuard, a permission framework
for agent skills. The key insight of SkillGuard is that skills should
be treated as permission-bearing executable artifacts rather than
implicitly trusted prompt snippets or simple tool wrappers. Skill-
Guard consists of five core components. First, it requires each skill
to declare its capability surface through a Skill Manifest, instantiates
declared permissions into runtime policy state, and mediates sensi-
tive behavior throughout execution. Second, it provides runtime
permission access control that maps host-specific tool invocations
to canonical capabilities and checks each action against the live
session policy. Third, it incorporates a user interaction mechanism
for sensitive permissions, allowing users to approve an action once,
approve it for the current session under the same constraints, or
deny it. Fourth, it enforces policies through a deny-by-default run-
time pipeline that composes workspace defaults, skill manifests,
persistent grants, and session approvals. For shell-style execution,
SkillGuard further invokes a permission-generation mini-agent
to infer lower-level capabilities required by commands and refer-
enced scripts before allowing execution. Fifth, it maintains runtime
behavior monitoring and audit logs, recording mediated actions,
capability mappings, policy sources, decisions, and reasons for de-
bugging and accountability.
We evaluate SkillGuard across five research questions covering
permission expressiveness, manifest completeness, defense effec-
tiveness, utility preservation, and efficiency. Using a corpus of 315
real-world skills collected from SkillsMP, we show that our taxon-
omy achieves 99.76% predefined-object coverage and 100% group-
level coverage over observed protected objects. On the SkillInject
benchmark, our automated manifest generation achieves 91.0% F1
at the capability level, with high recall over required permissions.
In adversarial evaluations, SkillGuard reduces attack success rate
from 32.37% to 23.02% under contextual injections and from 25.56%
to 16.67% under obvious injections.
In summary, this paper makes the following contributions:
• We formalize the security gap in skill ecosystems through a dual-
plane view of context influence and action side effects.
• We design SkillGuard, a skill-centric permission framework with
a manifest-driven model for context, action, delegation, and pol-
icy behaviors.
• We evaluate SkillGuard on real-world skills and SkillInject, show-
ing broad coverage, accurate manifests, lower attack success, and
preserved utility.

delegation logic to other skills, agents, or MCP servers [5, 7]. In
practice, a skill is not merely a thin wrapper over a tool, but can
instructively shape what the agent reads, how the agent reasons, and
what the agent is allowed to do. Recent discussions on skill systems

Today, however, the dominant skill management mechanism re-

selected, a skill may introduce new instructions or load additional
context to downstream components with little unified governance.
2.1
Problem Definition
Current agent ecosystems treat skills as useful productivity mod-
ules, but not as first-class security principals. This is problematic
because a skill can influence the agent along two distinct planes.
First, on the context plane, a skill can inject instructions, examples,
hidden assumptions, retrieved documents, or memory fragments
that reshape the agent’s reasoning trajectory before any external
action is taken. Second, on the action plane, a skill can trigger
tool calls, access files or secrets, communicate over the network, or
delegate to other components, thereby producing externally visible
side effects. A skill management framework must therefore govern
both what a skill can bring into the agent context and what it can
cause the agent to do.
Threat Model. We consider an adversary who aims to compro-
mise the confidentiality, integrity, or availability of an agent system
by exploiting the skill ecosystem. The attacker may publish a mali-
cious skill, poison a dependent skill, compromise a context source
consumed by a skill, or introduce malicious updates after a benign
initial release. We assume the base host runtime and the user are
benign, but the agent may faithfully follow harmful instructions
if those instructions are delivered through skill metadata, skill-
loaded context, tool outputs, memory, or delegated components.
This threat model extends prior MCP and tool-centric formula-
tions [8, 24], by moving the enforcement point from individual

Attack Surfaces. Based on existing literature and our empirical
observations on skill-specific risks [8, 14, 20, 26, 29, 32], we sum-
marize and focus on the following six representative attack classes:
1) Malicious instruction injection in SKILL.md. The most
direct attack is to embed misleading instructions into a skill package,
such as adding an apparently harmless note that instructs the agent
to forward task outputs to an attacker-controlled endpoint.
2) Context or permission overreach. The user task requires
only a narrow scope, but the skill elicits broader permissions or
reads more context than necessary. Even without overtly malicious
behavior, this violates least privilege and expands the attack surface.
3) Dependency or transitive skill poisoning. A benign skill
invokes another skill or dependency that carries malicious instruc-
tions, scripts, or context-loading logic, thereby bypassing local
checks through indirection.
4) Dependency or transitive information leakage. One skill
legitimately reads sensitive content, while another downstream
skill or component exfiltrates that content through external com-
munication or publication.
5) Context injection or prompt infection. The user task is
benign, but a skill reads documents, tool responses, memory items,
or retrieved content that contain adversarial instructions, which
are then propagated back into the main agent context.
6) Update or rug-pull attacks. A skill is initially benign and
gains trust, but a later update changes its manifest (the concept
will be introduced in Section 4.1), instructions, dependencies, or
effective behavior in a way that introduces new risks.
2.2
Related Work
Attacks on LLM Agents. Prompt injection is the most widely
studied attack vector against LLM-based systems [28, 34]. In a
direct prompt injection, the adversary crafts a user-facing input
that overrides the model’s system instructions, causing it to ignore
safety guidelines or execute unwanted actions. Indirect prompt
injection poses a subtle threat which attacker embeds malicious
instructions in external content (i.e., web pages, emails, or tool
outputs) that the agent processes during normal operation [10, 11].
Because LLM agents store all information in a shared context win-
dow, they cannot reliably distinguish between trusted instructions
and untrusted data, making indirect injection particularly difficult
to eliminate [33]. When agents operate relying more and more on
the skill ecosystem, with more than 1.4 million skills available at the
time of writing [1], the attack surface widens. For instance, skill in-
jection embeds adversarial instructions directly in skill files that the
agent loads as part of its normal workflow. Schmotz et al. [27] con-
struct the Skill-Inject benchmark to evaluate agent susceptibility to
such attacks, showing that both contextually blended and explicitly
visible injections can cause agents to perform unauthorized actions.
Safeguard Methods. To prevent AI Agent from the attacks to
perform unwanted actions, researchers have introduced many safe-
guard methods. To begin with, Progent [29] addresses over-privileged
tool use by placing a programmable policy layer between agents
and tools. Its domain-specific language expresses fine-grained con-
ditions on tool-call arguments with deterministic allow/forbid deci-
sions, fallback actions, and dynamic policy updates as agent state

11.2
Threats to Validity
The main internal validity threat in this study is that the manual
annotation involved in evaluating taxonomy expressiveness may
introduce human bias. To mitigate this, two authors independently
annotated the data and resolved disagreements through discussion,
yielding a Cohen’s Kappa of 0.656, indicating substantial agree-
ment. Another potential threat is that we follow prior work in
using an LLM-as-Judge approach to score ASR and TSR, which
may introduce bias if the judge misclassifies borderline cases or
hallucinates task outcomes. To mitigate this, we use Anthropic’s
Claude Sonnet 4.6 [4] as the judge, consistent with prior work [27].
Additionally, since our experiments involve API calls to remote
LLM endpoints, results may be affected by network fluctuations
and non-deterministic model outputs. To improve reproducibility,
all experiments are executed in isolated Docker containers with
fixed random seeds where applicable, and we make our datasets,
manifests, and evaluation scripts publicly available [2].
For external validity, due to the high cost of LLM API calls, we
evaluate with a single representative model (MiMo-V2.5-Pro [35])
and a single agent scaffold (Claude Code [6]). While we did not run
cross-model or cross-framework ablations, SkillGuard’s permission
enforcement is model-agnostic, and we expect the qualitative trends
observed in our experiments to hold across other foundation models
and agent frameworks. Regarding dataset scope, our taxonomy
expressiveness evaluation is conducted on 315 real-world skills from
SkillsMP. To ensure diversity, these skills are randomly sampled
from 63 categories with 5 skills per category, covering a broad range
of domains.
12
Conclusion
In this paper, we presented SkillGuard, a permission framework
for agent skills. SkillGuard treats skills as permission-bearing ex-
ecutable artifacts and governs both their context influence and
action side effects through manifest declarations, runtime access
control, user authorization, deny-by-default enforcement, capa-
bility inference, and behavior monitoring. Our evaluation on 315
real-world skills and SkillInject shows that SkillGuard provides
broad permission coverage, accurate manifest generation, reduced
attack success, and limited utility loss. These results suggest that
skill-centric runtime permissions offer a practical path toward safer
and more accountable agent ecosystems.
