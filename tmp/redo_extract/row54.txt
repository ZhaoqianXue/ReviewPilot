ABSTRACT
LLM agents complete complex tasks by composing multiple skills, and skill re-
trieval is a front-end stage for agents. Skill retrieval needs a different training signal
from document retrieval: top-K joint correctness depends not only on the seman-
tic relevance of each individual query–skill pair, but also on whether the skills
retrieved together can collaborate to fulfill the task under the given query. This
“skill compatibility” cannot be derived from independent relevance alone. Yet ex-
isting LLM-based data synthesis pipelines can produce a direct supervision sig-
nal for “which skills should not be jointly retrieved under this query”—namely
the LLM’s own rejection decisions—and this signal is routinely discarded as low-
quality data. To address this gap, we propose Reject-as-Resource Retriever (R3)
and construct R3-Skill, a bilingual (Chinese–English) skill retrieval benchmark
targeting realistic agent skill routing. R3-Skill spans four language directions, fea-
tures query phrasings close to real user requests, and is verified through multi-
expert cross-checking. The dataset contains 10,246 skills grouped into 8 thematic
super-domains; 41,592 accepted queries; and 32,828 LLM-rejected annotations,
further organized into an 8-class rejection-reason taxonomy. Unlike prior datasets,
R3-Skill keeps the rejection signal that is usually thrown away, and uses it as neg-
ative supervision for compatibility. On R3-Skill, we build a two-stage retrieval
system comprising R3-Embedding and R3-Reranker, with skill compatibility in-
corporated as an explicit training signal. We analyze this signal at the gradient
level: in the bi-encoder, the representation of any single skill is jointly determined
by multiple queries, so the “push-away” gradient injected by the compatibility sig-
nal is diluted by bilateral balancing and contributes little at the recall stage; in the
cross-encoder, each query–skill pair is scored independently, so the compatibility
signal can be used as graded supervision for ranking without loss. We therefore
place the compatibility signal at the cross-encoder stage, and ablation studies on
two datasets confirm this choice. The R3-Embedding + R3-Reranker pipeline at-
tains Hit@1 = 0.7714, NDCG@10 = 0.8327 and Set-Compat = 0.3525 on R3-Skill.
The dataset, training code and model weights are released as open source for agent
skill routing.

INTRODUCTION
1.1
LLM AGENTS AND SKILLS
Over the past year, agent systems have moved from early ReAct Yao et al. (2023), which interleaves
reasoning and tool calls into a trajectory, and Toolformer Schick et al. (2023), which enables mod-
els to learn API calls in a self-supervised manner, toward a higher-level reusable unit—the skill. In
October 2025, Anthropic formalized the Agent Skills specification ref (2025), packaging what used
to be scattered prompt templates, function wrappers and documentation snippets into a directory

containing a SKILL.md file with metadata, a body, and supporting scripts, all loaded on demand at
inference time. Skills have since been adopted by major agent platforms such as Claude Code, Codex
and Gemini CLI, and the community has accumulated tens to hundreds of thousands of skills within
months Anthropic (2025). Recent surveys Xu & Yan (2026); Jiang et al. (2026) position skills as the
third paradigm of agent capability extension, following prompt engineering and tool use. A skill and
a tool are not the same kind of object: a tool is an atomic “input →call →output” function, whereas
a skill teaches the agent how to handle a class of problems—covering call constraints, multi-step
procedures, canonical code and edge cases. Memento-Skills Zhou et al. (2026) further shows that,
when the skill library is treated as continuously updatable agent memory, improvements to the skills
themselves yield 26.2% / 116.2% relative accuracy gains on GAIA / HLE respectively. Completing a
complex task typically requires several skills working together—for example, “transcribe this meet-
ing recording and then summarize the key takeaways” calls for a speech-to-text skill followed by a
summarization skill, and a missing or mismatched skill can cause the task to fail.
What does a skill look like?
A typical skill contains:
• name: a short identifier, e.g. SendGrid Email Send;
• description: a one-line purpose, e.g. “Send transactional emails through SendGrid”;
• body: detailed call instructions (API shape, parameter constraints, platform dependencies,
best practices, canonical code), typically tens to hundreds of lines.
1.2
WHY SKILL RETRIEVAL MATTERS
The intuitive approach is to place all skills in the prompt and let the LLM choose. This is not viable
in real agent deployments:
(A) The skill inventory keeps growing. Public skill repositories have expanded from ~36K skills
indexed by SkillFlow Tagkopoulos et al. (2025), ~26K in SRA-Bench Su et al. (2026), and 280K+
reported by AgentSkillOS Li et al. (2026a), to even larger public corpora. As skill counts grow from
dozens to thousands or tens of thousands, an “all-prompt” approach runs into three problems: token
cost, inference latency and context-length limits. Prior work also shows the limits of injecting full skill
sets directly into the inference context: this approach brings in large amounts of irrelevant context,
and the model can only use these skills while reading them, rather than absorbing them as its own
capability Lu et al. (2026). Empirical token-length measurements on R3-Skill (Figure 1) show a long-
tailed distribution; injecting the entire library at once already exceeds the single-call context window
of mainstream inference services.

webhook callbacks; Postmark physically isolates transactional and marketing email to protect deliv-

(C) Multi-skill routing demands “minimal yet suﬀicient”. For each query the agent needs the right
set of skills: a missing skill makes the task unsolvable, and a conflicting one creates new failures.
SkillsBench provides a direct quantification: curated skills improve overall pass rate by +16.2pp, but
16 of 84 tasks show performance regressions Li et al. (2026b); Skills in the Wild further reports
diminishing returns under more realistic settings Liu et al. (2026); CoEvoSkills also observes that
human-authored skills bring substantially uneven gains across domains, with clear regressions in
some Zhang et al. (2026). The retriever must therefore both return the right candidates and order
them well, since their positions in the top-K shape downstream call success.
(D) Sandbox provisioning cost in real deployments. In production agent platforms, concurrent users
typically share an agent through per-session sandboxes: a sandbox is created when a user starts a
session and is reclaimed by a periodic sweep after the session has been idle for some time, so a one-
sandbox-per-user model is infeasible. Each sandbox must install the skills it actually needs before the
agent can run. If every sandbox loads the full skill library, the install / reset latency grows roughly
linearly with the library size and quickly dominates the user-perceived cold-start time. Routing only
the K skills each sandbox actually needs is therefore an engineering requirement, not just a quality
issue.
1.3
SKILL RETRIEVAL ̸= DOCUMENT RETRIEVAL
Document retrieval typically assumes that “two documents being retrieved together for the same
query” is harmless—if both are relevant, returning them together introduces no error. Skill retrieval
is different. The retriever returns a set of capabilities the agent will actually invoke. Whether two
skills can run together under a particular query depends on the query itself; a different query over the
same pair can flip the verdict (Figure 2). “Whether two skills should be jointly retrieved” is therefore
not a global binary relation between skills, but must be assessed under a given query. Concurrent
work Skill-RAG also points out that the bottleneck of many hard cases in RAG lies not in missing
evidence but in a structural alignment gap between the query and the evidence space, which motivates
its post-hoc skill selection mechanism Wei et al. (2026). We focus on the retrieval stage itself: in the
training objective, “relevance” should depend on the specific query rather than be determined by the
skill alone. We now formalize skill compatibility.

1.4
STATUS QUO AND GAPS IN SKILL RETRIEVAL DATASETS
Adding skill compatibility into the training objective is mainly limited by the lack of suitable
training data. Existing skill retrieval datasets fall roughly into two categories: (i) end-to-end task
benchmarks—SkillsBench, SRA-Bench, SkillFlow—which mainly target the post-retrieval incorpo-
ration/application stage and lack the scale to train a retriever; (ii) training resources designed specif-
ically for skill retrieval Cho et al. (2026). Both inherit the contrastive paradigm from document re-
trieval (the DPR Karpukhin et al. (2020) / ANCE Xiong et al. (2020) / RocketQA Qu et al. (2021) line,
with BM25 Robertson & Zaragoza (2009) as a sparse baseline) and are fairly mature on document
retrieval. Toward the goal of agent skill routing, however, three gaps remain:
1. LLM rejection signal is discarded. Existing query–skill synthesis pipelines drop a sample as
soon as the LLM judges a skill set “not naturally combinable”—yet this is precisely where
compatibility-oriented negatives are densest.
2. Cross-lingual coverage is lacking. Existing skill retrieval resources cover English only. Clus-
ter analysis of 26,502 public skills on the ClawHub platform by Red Skills or Blue Skills
shows that English skills lean toward capability modules while Chinese skills lean toward
scenario packaging Hu et al. (2026)—meaning that the linguistic asymmetry of “a Chinese
query retrieving English skills” is worse in real deployments. While multilingual retrievers
(e.g. BGE-M3 Chen et al. (2024)) achieve query–document-level Chinese–English align-
ment, existing datasets still do not provide a training signal for cross-lingual skill compati-
bility under given queries.
3. Test-set query phrasing diverges from real user requests. Queries generated by LLMs under
structured prompts tend to be long, formal, and dense with technical terms, so a retriever
can score well just by matching keywords. Skills in the Wild reports a similar phenomenon:
when the agent must self-retrieve from a 34k real skill pool with progressively more realistic
test settings, pass rate drops with diﬀiculty and approaches a no-skill baseline at the strictest
setting.
4

This work targets the three gaps above: we build R3-Skill, retain LLM-judged non-co-executable
samples as supervision for skill compatibility, cover four query language directions across Chinese
and English, and apply LLM rewriting to the test queries to better resemble real user requests. On
top of this dataset we train two retrieval models, R3-Embedding and R3-Reranker.
