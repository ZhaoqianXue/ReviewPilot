# Biomedicine r3 schema next-action repair plan

> **Execution method:** Subagent-Driven Development with an implementer, independent specification review, and independent quality review before a clean r4 browser rerun.

**Goal:** Make schema-generation replies and `next_actions` deterministically direct the user to Finalize Schema, then direct a finalized schema to Information Extraction, with no LLM-based workflow routing.

**Evidence:** `docs/internal-testing/runs/2026-07-13-biomedicine-r3.md`, `docs/internal-testing/evidence/biomedicine-r3/07-schema-next-action-conflict.png`, and the redacted task summary. The UI required Finalize Schema while the completed task reply said Categorization & Analysis.

**Root cause:** `LeadAgent._stage_reply()` gives an LLM a stage-to-next-action policy that omits `prompt_extraction`, so the model inferred the later extraction policy and named Categorization. Independently, `_next_actions("prompt_extraction")` returns `download_pdfs`, which is also wrong for an unfinalized generated schema. Routing is deterministic application logic and must not be delegated to the model. Confidence: high.

## Task 1: Make schema routing deterministic

**Files:**

- Modify: `agents/lead_agent.py`
- Modify: `tests/test_lead_agent.py`
- Modify if endpoint contract coverage is needed: `tests/test_web_app.py`

### Step 1: Add failing outcome and routing tests

For a successful `generate-schema` result with 10 fields, assert the returned and persisted assistant reply tells the user to review/finalize the schema and does not mention Categorization. Assert `next_actions == ["finalize_schema"]` while the schema is a draft. Assert the existing finalized-schema action returns `next_actions == ["run_extraction"]` and says to run Information Extraction.

Add a policy test proving prompt-extraction routing is generated by deterministic code, not by accepting an LLM-proposed next action. The current implementation must fail on both the wrong `_next_actions` mapping and the unconstrained LLM reply path.

### Step 2: Implement the minimum deterministic schema reply

Special-case the `prompt_extraction` stage in the action-result path or `_stage_reply()` so schema generation returns a concise deterministic reply using only structured `field_count` when available and always names Finalize Schema. Change `_next_actions("prompt_extraction")` to `finalize_schema`. Preserve the existing `_schema_action_result()` behavior that chooses `run_extraction` only when `is_schema_finalized(project_path)` is true. Do not redesign other stage summaries in this task.
