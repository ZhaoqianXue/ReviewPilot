# Follow-up bug audit — 2026-09-12

This audit supplements the prototype parity audit. The initial 826-test suite passed, but additional reproductions and browser interaction exposed the defects below. Prior workspace edits were retained. All audit projects were temporary; production examples were not edited.

## Fixed defects

| ID | Reproduction / impact | Correction and evidence |
|---|---|---|
| B01 | Exclude paper A, include paper B, then re-include A: B could inherit A's `row1` PDF. | Respect explicit PDF identity after every membership change; refuse ambiguous positional PDF candidates. Three-edit regression verifies each paper's PDF ownership. |
| B02 | Human inclusion/exclusion updated visible totals but left `removed.by_relevance` unchanged. | Both statistics exports now conserve the collection and reflect current reviewed exclusions. Tested both directions. |
| B03 | Refresh kept an unsaved query but restored chips from the saved query. | Reconstruct chips from the restored query. Node regression executes the actual restore block. |
| B04 | A late category decision response from project A could clear project B's pending state. | Bind the whole request, including cleanup, to navigation ownership. Test also simulates task-monitor generation changes during successful state refresh. Browser: skip → finalize → reload succeeds. |
| B05 | Non-object JSON, malformed category selection and nonfinite numbers could produce HTTP 500 errors. | Validate JSON shape and finite numbers before dispatch, including exponent overflow; return HTTP 400 without project writes. Endpoint matrix covers create/setup/chat/memory settings and category selection. |
| B06 | Date metadata containing zero month/day could be treated as a real date and excluded. | Invalid dates remain uncertain and retained for review. Tests cover three zero-component forms. |
| B07 | Arrays/objects from extraction could contain nested NaN/Infinity. | Apply finite JSON validation to model values and human corrections. |
| B08 | Equal native IDs across sources collided; ambiguous sample selection could silently choose the last row. | Namespace review keys by known source, preserve extraction identity, reject ambiguous selection/PDF/evidence lookups. Legacy records with missing source retain their original key scheme. |
| B09 | An invalid manual Boolean query could reach setup confirmation and then fail collection. | Parse explicit manual queries before setup mutation or downstream invalidation. |
| B10 | Deleting a conversation during a chat reply could race message/schema publication. | Reserve the project for every chat context. Concurrent deletion returns HTTP 409 until the response is saved. |
| B11 | User/model schema fields such as `paper_id` or `field_evidence` could overwrite metadata; malformed/duplicate fields could be silently saved. | Validate field shape, unique normalized names, reserved metadata names, supported types and constraints before saving/finalizing/extracting. Tests verify invalid schemas leave the prior schema intact and an invalid model field cannot replace paper identity. |
| B12 | Clicking Remove on a chip containing quotes did not remove it. | Compare decoded DOM text with decoded chip values. Found in browser; covered by Node regression and browser removal/reload verification. Apostrophes inside words also retain correct Boolean grouping. |
| B13 | Preview could borrow another paper's result by row position or native ID, or show stale extraction/cache data as current. | Check identity/source compatibility and stage freshness, limit positional fallback to genuinely unidentified legacy rows, and bind cache validity/publication to source and schema revisions. Existing version-1 preview caches are ignored and can be regenerated. |
| B14 | At widths ≤760px, the whole conversation sidebar vanished with no replacement. | Add a collapsible Conversations entry with history/search/new-review controls. Verified at 390×844, including project switching. |
| B15 | Help & support looked clickable but had no action. | Add an in-app workflow guide, accessible from ordinary projects and protected examples, with Close/Escape controls. |

## Limits and compatibility

This is a regression and implementation audit, not a proof that every possible defect is absent. External scholarly search availability/rate limits, institutional PDF access and live model quality were not comprehensively retested. Historical PDFs or extraction records that were already incorrectly associated cannot be reconstructed from missing provenance; affected records need a fresh retrieval/extraction run. No production data migration or deployment was performed.

The 16 new tests supplement existing coverage of the five-stage workflow, recovery, revision conflicts, local decisions, explicit configuration reuse, session history and exports. Cosmetic feature enhancements from the earlier parity report are not evidence of data correctness and are not counted as passing functional tests here.
